# Spell Wheel controller candidate

This candidate is based on `f2053f3439b23c5f9f53e15c383f2488847a1354`, the follow-up to the accepted settings-panel release. It targets the existing Windows x64 mod loader setup. GitHub Actions publishes on a qualifying push to `master`. A manual candidate run uses `publish_release=false`.

## Controller behavior

- A press shorter than `controller_wheel_open_delay` requests one native cycle after release. At the threshold the press belongs to the wheel. If the first sample at or beyond the threshold is already up, the press is consumed and the wheel has no held frame to display. Each enabled wheel uses the game's resolved controller bindings. Disabled wheels use the original game checks.
- With `switch_instantly=true`, selection applies while the controller wheel is open. With it set to `false`, selection applies on release. After a normal close the sound condition uses the actual active equipment slot and parameter ID. A changed, accepted selection plays the game's equipment change event once. Returning to the starting slot, releasing with no selection, and rejected or cancelled selections stay silent. Cancellation keeps completed instant selections.
- The zoom context grants the press to the game through release. Taking over a pending or visible press cancels the controller interaction. Opening the settings panel, leaving focus or gameplay, disconnecting, and changing a binding also cancel the interaction and require a released button to rearm.
- The indicator points to the highlighted slot center. The current selection holds for an additional **8% of one slot's angular width** beyond either edge. Passing that margin switches immediately. `controller_min_radius` remains the radial gate. Both wheel styles use the same selection rule. The settings preview draws without selecting or committing.

The candidate uses the existing delay, radius, wheel enablement, and instant-switch settings. Their defaults, TOML keys, and panel Save and reload semantics are the same as the accepted release. Controller sampling uses XInput player index 0, the existing player's index. Keyboard and mouse selection retain their existing path.

## Native evidence and in-game checks

The first candidate (`61678d3`) loaded XInput and rendering on App Ver. 1.17.2 / Calibrations Ver. 1.17.3 and rejected all six input and HUD signatures. Its log omitted the observed bytes, so the cause of the mismatches remains unconfirmed. It also stopped after its first probe. This candidate reads exact bytes from the loaded executable through the Windows process-memory API and retries when the signatures are unavailable. The log records the executable's product version, the observed bytes or read errors, and the first call to each installed hook.

The candidate supports the published layouts for the original 1.17 Tarnished Edition and 1.17.2. It selects a single profile after validating all six signatures and takes the sound and vtable addresses from that profile. Startup should log `Matched all six controller hook signatures` and `Controller switch hooks ready` with `spells=true quick_items=true`. Ambiguous or incomplete profile matches leave game input native while probing continues. [1.17 address reference](https://github.com/LorenzoFerri/RadialMenu/commit/a3767116ed364d4c88b4f02652be34e9ed01ea09) · [1.17.2 address reference](https://github.com/LorenzoFerri/RadialMenu/commit/9f18b00a49c86ae70de96612d92f5a46e91f8470)

The matching RadialMenu source records two spell-request checks when the spell HUD is visible, serving HUD visibility and cycling within one HUD update. Item requests use one check. The candidate scopes those responses to one equipment HUD update per tap. [Native request and HUD reference](https://github.com/LorenzoFerri/RadialMenu/blob/9f18b00a49c86ae70de96612d92f5a46e91f8470/src/game/input/radial_switch.cpp)

In-game checks on `83a128d` passed on App Ver. 1.17.2 / Calibrations Ver. 1.17.3 except for the close sound. The log shows both wheel hooks running and the audio guard rejecting the sound path. The earlier guard combined the sound routine's byte check with an address-order assumption about the event table, so the log did not distinguish those conditions.

The sound candidate uses the documented native menu event for both wheels. It still requires the sound routine's expected bytes and a readable event table from the matched game profile. It removes the address-order restriction, retries validation on the next changed close if a read fails, and logs the first call for each wheel. A changed wheel close invokes the sound-only routine after the slot readback. The revised playback still needs in-game confirmation. [Version-matched sound reference](https://github.com/LorenzoFerri/RadialMenu/blob/9f18b00a49c86ae70de96612d92f5a46e91f8470/src/game/input/radial_switch.cpp#L235-L253)

The pinned game bindings document the local player's `ChrInsFlags1c5::precision_shooting` as the bow precision camera flag. Telescope checks use an active special effect with `stateInfo = 15`, labeled Telescope in the game-data references. These reads and the ownership logic are in the candidate. Their update order and live values in third-person, ranged aim, and Telescope still need an in-game trace. With the existing `debugging` key enabled, `Controller camera state (precision aim, telescope)` log lines show changes between those states. [Pinned game bindings](https://github.com/vswarte/fromsoftware-rs/blob/09a4208ac26af4ae07b08c5273ee0e89faf97cb8/crates/eldenring/src/cs/chr_ins.rs#L439-L444) · [Telescope effect 3240](https://github.com/soulsmods/Paramdex/blob/ff7245e524329bc3eab00036723d2bd53384cedf/ER/Names/SpEffectParam.txt#L434) · [Telescope state info](https://github.com/The-Grand-Archives/Elden-Ring-CT-TGA/blob/393c439e72ad48128efdc5e30fc3feb4bfbd210f/CheatTable/CheatEntries/Open%20-%20The%20Grand%20Archives%20-%20Elden%20Ring/MiscWIP/Dropdowns/STATE_INFO.xml#L19)

## Windows acceptance

1. Close Elden Ring. Back up the active DLL and `spellwheel.toml` outside mod-loading directories. Install only the candidate DLL and keep one active Spell Wheel DLL. Leave the existing TOML in place. Set the usual Frame Generation state before launch and keep that state throughout the test.
2. On each wheel, first try a short press and a full hold. Expect one native cycle and sound after tap release, and the wheel without any cycling on hold. The startup log is in `spellwheel/spellwheel.log` beside the DLL. If either wheel still falls through to native cycling, attach the fresh log. Then test presses just below and above the threshold, game remaps, disabled wheels, and spell taps with the equipment HUD visible and hidden.
3. For both `switch_instantly` modes, test selecting a different slot, returning to the starting slot, and releasing without a selection on both wheels. Check actual slot, timing, and sound count. On a normal changed close, expect one equipment click. If it is missing, attach the fresh log to show whether the sound routine was called. Use a menu, focus loss, or unplug during an open wheel to confirm cancellation and rearming.
4. Confirm zoom in and out using ranged first-person aim and the Telescope. Exit zoom while holding a switch button, then release. Enter zoom during a pending press and while the wheel is open. Expect native zoom, no wheel or deferred tap, and no new selection or close sound on cancellation. In instant mode, verify any selection applied before cancellation remains. If a context fails, send the nearby camera-state log lines from third-person, ranged aim and Telescope, along with the game version.
5. On sparse and crowded wheels, move near a slot boundary and across the wraparound seam. Small jitter should keep the highlight and snapped indicator steady. Deliberate movement should switch immediately. Check first selection and movement back inside the radial gate.
6. Open and close settings using your saved shortcut. Check single activation, frozen preview, camera and cycling suppression while the panel owns input, a reversible Save or Discard, HDR readability, and normal gameplay controls after closing. Check original keyboard and mouse wheel controls, scrolling, camera movement, and ordinary action buttons.

Rollback by closing the game and restoring just the backed-up DLL, or the accepted panel DLL with SHA-256 `b564a8bbf477036a485cffd8a931d8b5a06f3dd89523f171d07e82f479b3022d`. Keep the TOML and keep just one DLL active. [Accepted settings-panel release](https://github.com/BandarasX/SpellWheel/releases/tag/settings-panel-56c8ed2)
